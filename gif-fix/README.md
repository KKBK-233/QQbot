# GIF 表情识别修复

45 帧、4.5 秒的“达妮娅看看你”GIF 被旧逻辑只取首帧：`uint8` 数组相减后平方溢出，均方差最高约 73，达不到默认阈值 1000；正确浮点计算最高约 4773。

`preview.py` 按播放时长取最多 12 帧，覆盖首尾，带序号与时间的网格保留微笑、眨眼、歪头、靠近打量等动作。透明区域铺白底，网格尺寸有上限；同一接口参数继续兼容。

识别提示优先描述可见动作和文字；不把单帧半闭眼直接判成嫌弃，不把表情标签当作发送者真实情绪。保留最多 5 个逗号标签，与原生表情选择兼容。

同一 `deepseek-flash`、temperature=0 的三次对照：旧输入为“无语、尴尬、假笑、敷衍、沉默”；多帧旧提示为“可爱、卖萌、眨眼、心动、温柔”；多帧新提示为“眨眼、注视、微笑、歪头、语气需结合上下文”。这是单样本证据，不保证所有 GIF 都能理解准确。

部署：`MaiBot/.venv/bin/python /mnt/d/code/web/QQbot/gif-fix/deploy.py`。仅更改 GIF 抽帧函数、新辅助模块和中文表情提示，逐文件备份，保留其他补丁。

测试：分别运行 `MaiBot/.venv/bin/python /mnt/d/code/web/QQbot/gif-fix/test_preview.py` 和 `test_cache.py`，共 10 项。覆盖帧差溢出回归、非均匀时长、末帧、尺寸上限、单帧、透明背景和异常输入；缓存更正覆盖同标签的其他媒体、真人文字、幂等、定位失败及 `is_emoji=0` 的真实入站形式。

`repair_cache.py` 按 SHA-256 校验原 GIF 后，备份并事务更新该表情缓存及精确关联消息的机器描述。真人发言、原 GIF、历史规划快照不改写。已有其他 GIF 缓存不会批量重新识别。

“达妮娅看看你”的名称按用户纠正补入；正式模型入口独立识别出“眨眼、微笑、歪头、注视镜头、温柔”。已更正该媒体两条历史机器描述，缓存为“达妮娅看看你,微笑眨眼,歪头,靠近打量,语气需结合上下文”。`verify_runtime.py` 验证部署源码、45 帧原图、12 帧预览、原生缓存读取与历史消息一致，不调用模型或发送 QQ 消息。QQ 登录在重载后验证保持。

加载前只停止和启动 `maibot`，QQ 与中间件保持在线。源码回滚时恢复 `data/gif-fix-backups/` 中的文件；缓存恢复使用 `cache.json` 中的原字段及 Base64 MessagePack。
