# KKBK 版本化工作流

工作流为 MaiBot 现有任务层提供自然语言指导，用来描述工具任务的用途、适用范围和建议步骤。它不是强制 DAG 执行器：不会自动调度步骤、强制调用工具，也不保证模型逐项执行。现有用户目标、工具权限、预算及宿主规则优先。

本步仅接入工作流基础，不修改人设、记忆、模型路由或配额。完整源码开发与发布由后续阶段实现，本步尚未接通开发代理与发布器。

## 文件和启用方式

固定读取 MaiBot 仓库下的 `workflows/`，聊天内容、网页和模型参数不能指定其他目录或修改启用清单。

```text
workflows/
  enabled.json
  catalog/
    conservative-web-research/
      1.0.0.json
```

`enabled.json` 显式选择版本，未列出的文件不加载；`enabled: []` 表示关闭全部指导。

```json
{
  "schema_version": 1,
  "enabled": [
    {
      "id": "conservative-web-research",
      "version": "1.0.0",
      "file": "catalog/conservative-web-research/1.0.0.json"
    }
  ]
}
```

工作流文件包含且仅包含以下字段，文件中的 `id`、`version` 必须与清单一致：

```json
{
  "schema_version": 1,
  "id": "conservative-web-research",
  "version": "1.0.0",
  "purpose": "使用实际取得的来源查证事实",
  "scope": "仅适用于使用联网工具的查证任务",
  "tools": ["web_search", "read_webpage"],
  "steps": ["按用户原始问题确认来源，回答时附实际取得的链接"]
}
```

`tools` 是指导的适用工具集合，只有这些工具全部处于本轮可用集合中才注入该指导。它不会开放工具或要求全部调用；是否适用任务由自然语言范围说明约束。本步附带的工作流只涉及已有的 `web_search`、`read_webpage`。

格式约束：`schema_version` 为整数 `1`；`id` 为小写字母开头、最多 64 字符的字母数字及 `_`、`-`；`version` 为不带前导零的 `X.y.z`。单文件最多 65536 字节，最多启用 16 项，同一 ID 只能启用一个版本。`tools`、`steps` 各包含 1～16 项；重复工具名、重复 JSON 键、未知字段及非标准数值均报错。`file` 必须位于 `catalog/` 内，绝对路径、路径穿越及符号链接越界均报错。

## 任务快照和轻重路径

每次 `_turn` 开始时在线程中加载一次清单及工作流，并冻结为不可变快照。普通轻聊天不携带工作流大段指导，也不因此增加模型调用。只有现有轻层决策升级为 `escalate`，才将匹配指导注入工具阶段。

进行中的工具多轮和模型重试共用这个快照。任务执行期间即使切换清单，当前任务继续使用旧版本，下一任务才读取新版本。模型重试只重发当前上下文，保留已完成工具的结果，不从头重放工具。

日志 `workflow_snapshot` 记录任务入口的清单 SHA-256、工作流 ID、版本、内容 SHA-256 或配置错误；`workflow_tools` 额外记录实际注入指导的工作流。清单摘要基于原始文件字节，工作流摘要基于键排序、紧凑 JSON 的规范化内容，单纯缩进变化不会改变工作流内容摘要。

同版本内容改动没有被禁止，也没有持久化历史校验；它只能通过内容 SHA-256 变化辨认。因此发布新内容应创建新版本文件，不要原地覆盖已发布版本。

## 校验、发布和回退

可在仓库根目录独立校验，不加载宿主登录、数据库或模型：

```powershell
python -X utf8 -B -m src.kkbk_engine.workflows
```

成功返回退出码 `0`；错误输出诊断并返回 `1`。旧安装完全没有 `workflows/` 目录时，兼容为空快照，保留原工具路径。目录已存在却缺少 `enabled.json` 属于配置错误；关闭工作流应写入空清单，而不是删除清单。

配置错误使本轮启用集合整体失败，不沿用上轮成功版本。轻聊天仍可正常回答；若轻层请求升级工具任务，宿主会返回配置未通过校验的说明，拒绝进入工具阶段。恢复正确配置后，下一任务重新读取。

维护者发布时先写入新的版本文件并完成校验，再在 `workflows/` 同一文件系统内将完整的新清单写到临时文件，通过 `os.replace` 等原子重命名切换为 `enabled.json`。不要逐行改写线上清单，也不要同步覆盖工作流正文。加载器会在读取结束时复读清单，发现读取期间清单变化便拒绝该轮，以免混合启用集合。

回退采用同样的原子切换方式，让清单重新指向保留的旧版本文件。切换不影响已开始任务的固定快照。这里描述的是文件发布方法；代码提交和离线校验本身不代表已经部署、重启或完成真实群聊验收。
