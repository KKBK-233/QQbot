# 人物画像与记忆修复

人物按平台账号绑定，模型只选择真人原句。稳定自述保留原谓语并进入稳定了解或相处偏好；其它有用原话进入近期互动，保留30天，不能推断身份或性格。一次提取覆盖近期多位发言者。

`remember_memory` 用于用户明确要求记住/更正的普通聊天。通用笔记保存到原生长期记忆；明确自述进入人物账本。只有拿到落库段落hash才返回成功。更正先保存新原话，再撤回同一用户旧段落和旧画像事实；失败时明确报告部分完成。

摘要采用真人消息ID、作者和完整原句；服务端重建正文，丢弃模型自由生成的事实值、实体、关系，不采用机器人自述。当前原生无embedding，继续使用关键词和现有检索；本文不宣称已具备语义向量召回。

首次启动迁移自动画像的旧模型概括：按原消息作者重建，无法验证的内容撤回到原生回收站；已知错误角色摘要和指尖测试细节撤回，不补录局部绘图参数。数据库备份为`MaiBot/data/a-memorix/repair-v2-before.sqlite`，游标为`repair-v2-state.json`。手工资料和生图参考卡不变。

部署：WSL虚拟环境执行`memory-fix/deploy.py`和`configure.py`，无进行中的生图任务后仅重启MaiBot。源码修改有锚点检查、语法检查和备份，重新部署幂等；上游源码升级后应重新检查锚点。

验证：`python -m unittest discover -s memory-fix -p test_*.py`，WSL虚拟环境执行`verify_runtime.py`。使用真实原生临时存储，不调用模型、生图或QQ；覆盖作者与会话隔离、断章取义、模型捏造、幂等、画像投影、摘要、保存失败、更正撤回。`inspect_runtime.py`会查询画像，原生服务可能刷新画像缓存；不作为严格只读检查入口。

## 人物索引

`person_index.py`将所有历史真人发言者、账号、曾用昵称、群名片和有作者证据的记忆关联投影到`MaiBot/data/a-memorix/person-index.sqlite`。原消息和长期记忆只读，不要求先有画像；默认每30秒按需刷新，新发言者自动加入，删除/到期记忆关联同步移除。派生索引可以从原库完整重建，不复制消息正文，也不猜测段落里提到的人就是记忆所有者。

`list_known_people`支持昵称/别名查询、分页和每人两条历史消息片段。群内只列该群历史发言者；私聊只列当前对象。目录说明历史发言者不等于实时成员名单，画像不足不等于忘记。规划器每轮自动获得最多100人的轻量名字目录，不受3人详细画像注入上限限制；完整查询可翻页。人物画像工具补充同一账号在当前会话的最多4条历史消息，媒体识别文本及截取片段不会写成稳定事实。

部署索引：WSL虚拟环境执行`deploy_index.py --check`，再执行`deploy_index.py`；执行`verify_index_runtime.py`回填并验收真实数据，不调用模型或QQ。确认没有进行中的生图任务后仅重启MaiBot。原有`deploy.py`可重复执行，索引补丁与证据修复补丁兼容。
