# 静态审阅核对与修正范围

2026-10-21（UTC-7）。本轮按管理员要求不改 DSH 开发执行、会话控制、发布授权及行为活跃度策略。

| 审阅项 | 核对结论 | 本轮处理 |
| --- | --- | --- |
| 1 工作流持久注入 | 工作流确实是高信任持久指导；宿主已核验实际管理员来源。“原文来自本人”本身不能证明引用或批准内容正确，也不能把管理员明确接受方案视为无效授权 | 不新增发布闸门，不变更 DSH 授权与工作流信任层级 |
| 2 缓存布局 | 动态教学和工具清单改变系统内容，前插工作流也会改变消息前缀；不是所有缓存都会失效，变化位置前仍可能命中，真实效果还取决于上游工具 Schema 与序列化 | 教学仅在重任务末尾召回，动态工具清单移到本轮情况，工作流末尾追加；测试验证消息前缀，不虚报实际命中率或节省比例 |
| 3 分散身份及工具白名单 | 属实，旧教师账号和入站补全绕开配置 | 教师由身份配置解析，唯一维护者变更可同步生效；多维护者需明确教师；入站使用当前 bot 账号，插件工具集集中到 EngineConfig。独立 worker 的授权配置按 DSH 不动要求保留 |
| 4 运行时职责和格式 | 职责集中属实；一次全面拆分会扩大本轮范围 | 拆出请求上下文、工具执行及原生 Item 构造；主类保留回合编排，开发通知轮询原样保留；格式化本轮相关引擎文件，未格式化或重构 DSH 模块 |
| 5 字符串判错与额度失败 | 属实；错误文字中的端口或数字可能被误认为 HTTP 状态 | 沿 original_exception/cause/context 读取状态码及结构化额度代码；只重试明确临时错误，额度不足不继续请求模型，保留已有检索来源并明确失败原因 |
| 6 教学直接查询原生 SQLite | 属实，且没有现成的有效教学枚举服务接口；通用语义搜索不能等价替代确定性去重和删除检查 | 新增 MemoryService.list_teachings；数据库字段依赖集中到服务查询适配器，使用精确 JSON 字段过滤，结构变化明确报错。保留原生存储及已有教学，没有另建或迁移记忆库 |
| 7 fork/submodule 与补丁归属 | 合理的后续维护方案，但不是现有源码运行的直接缺陷；它会影响公开快照、固定基线克隆及多仓组合副本 | 本轮不迁移仓库，不把现有外部补丁误标为已归并；后续与多仓开发副本一起设计 |
| 8 设计、历史、状态混写 | 属实，历史“尚未”容易被误读为现在状态 | 拆为稳定 harness-plan、CHANGELOG 和 status 表，保留历史证据 |
| 9 行为回放闸门 | 行为评估能提供信息，但覆盖率及调用次数阈值需要另行定义，不能直接等价于质量 | 按管理员明确意见不加闸门，不限制变吵；DSH 相关行为策略不变 |

所有缓存与异常回归均离线执行，不请求外部模型或发送 QQ 消息。教学服务只集中查询适配，后续原生存储改变仍需在该适配器更新，不能宣称已消除底层数据库依赖。
