## 学习、装饰与旧链路

| 功能 | 当前状态 | 成本/效果 | 精简建议 |
| --- | --- | --- | --- |
| 表情包自动收集与维护 | `emoji.steal_emoji=true`，周期维护调度存在 | 媒体存储、描述/分类可能调用模型 | 第一批候选：先关自动收集，保留收到表情的基本解析 |
| 表情替换 | 配置 `emoji.do_replace=true` | 旧回复风格处理 | 可去掉装饰行为；需区分新引擎直接文本发送 |
| 表达学习与自省 | 配置保留；旧 Maisaka 有学习器，新引擎不创建它们 | 学习和检查会调用模型 | 第一批候选；新群未依赖，不应据全局配置宣称新群也在学习 |
| 黑话推断和学习 | 旧 Maisaka 链路具备，已有历史调用记录 | 模型提取、推断和数据库记录 | 可关闭/归档学习，保留已有词条作为资料 |
| 行为场景分析与行为学习 | 场景分析属于旧链路；实验行为学习总开关 false | 旧会话仍可能有相关分析；不能把 false 当所有分析停了 | 待确认旧会话用途后统一收束 |
| 中期记忆压缩 | `chat.mid_term_memory=true`，由旧 Maisaka 负责 | 独立摘要请求，与 A_Memorix 不完全相同 | 旧链路退出后可归档；先不改记忆相关配置 |
| 随机错字、回复分句 | 配置开启，主要属于旧回复后处理 | 修改表达，不构成能力提升 | 建议关闭装饰效果；新引擎直接发送未证明使用这些开关 |
| 多人设、注意力漂移、实验富回复 | 概率 0 或开关关闭 | 主要保留源码/配置 | 已关闭，不应把源码行数算成运行费用 |
| 语音 ASR、遥测上传、事件循环看门狗 | 配置关闭 | 当前无对应启用功能 | 暂无需继续“停用”，以后可整理配置 |
| 控制台输入 | 配置开启，但 Supervisor 无交互终端会跳过 | 不提供实际群能力 | 可关闭配置以减少干扰 |
| MCP | 总开关开启，但配置服务器 0 个 | 新引擎没有注册 MCP provider，仅有内置与插件 provider | 当前未提供额外能力，可关闭空配置；不等于已有可用 MCP 开发工具 |
| HTML 浏览器渲染 | 配置开启，按需服务 | 浏览器进程与依赖可能占空间/内存，开关不证明当前启动了浏览器 | 未使用卡片/渲染时可关闭，先核对调用方 |

## 记忆：保留现有模块

依照既定决定不改 A_Memorix。它当前还包含以下附属能力，后续如确有消耗问题再针对性讨论：

- 人物事实抽取、历史证据复核、人物画像与刷新。
- 聊天摘要写回、跨会话共享与启发式召回。
- 图片记忆写回、图片补偿任务。
- 情节切分与整理、反馈纠错、记忆撤回和重建。
- 稀疏检索、向量回填、清理、持久化。

已知 embedding 未配置，向量相关路径有降级和失败日志。失败清理任务不直接等于付费模型调用；本轮不补模型、不清库、不重建记忆。

## 建议的精简顺序

1. 本轮已执行：移除离线 Python。
2. 下一批供用户选择：表情自动收集/替换、表达自省与学习、黑话学习、随机错字、碎片分句、无用控制台配置。

4. 等其他会话核对完，再清理旧 Maisaka 规划/回复/学习器和重复兼容钩子。
5. 生图角色记忆、MCP、HTML 渲染、微信人工验证和登录服务按实际使用场景选择。
6. 核心消息、搜索、生图、按需识图、现有记忆与必要请求路由保留。

以上第 2–5 项仅是清单和建议，尚未实施；不要把盘点当成批量关闭授权。后续实施阶段暂停在这轮精简选择之前。
