## 群内使用

- 主动教学示例：`技术仓库可以先用搜索引擎查，再用 GitHub 搜索复核，最后比较两边来源。` 不需要补“记住这条”。
- 教学识别后调用 `learn_teaching`，模型整理总结、关键词和来源消息；真实保存成功后回复“我记住了”及复述，不另加一轮模型调用。
- 需要修改工作流或代码时再提交开发候选；学到一个方法不等于每次都启动开发代理。
- 一次性指导示例：`这次先查官方原文，不改工作流。` 由当前任务处理，不提交持久开发。
- 源码开发示例：`修复搜索插件的这个错误，补充回归测试。`
- 查询：`查看最近开发任务` 或 `查询开发任务 TASK_ID`。
- 取消：`取消开发任务 TASK_ID`。排队任务立即取消，执行中任务回收进程组；已经完成的候选不因此回滚。
- 回退：`撤销最近一次工作流发布`。恢复该次发布前的线上工作流。

## 本机服务与数据

`python -m dev_worker serve` 运行常驻服务，由 Supervisor 的 `dev-worker` 管理。服务代码快照位于 `/home/qqbot/dev-harness/worker-code/`，账本沿用 `/home/qqbot/dev-harness/worker.sqlite3`。只监听 `/home/qqbot/dev-harness/run/control.sock`，目录权限 0700、socket 权限 0600，不开放 TCP 端口。

Unix socket 信任同用户的 QQ 宿主进程，不提供远程认证，也不防御已经能以同一宿主用户任意执行代码的插件。服务再次检查管理员和群范围；不接收模型指定的仓库路径、Git 基线、测试命令或执行权限。

模型提交与后台执行分离。服务快速返回任务编号，worker 在独立副本执行；任务并发仍为 1。持久工作流候选只允许改动 `workflows/` 与 `pytests/kkbk_engine/`，超出范围则失败；明确的源码开发任务保留完整项目修改能力。

同一平台、会话和消息编号形成持久去重键。模型补试、重复工具调用和服务重启仍返回同一任务，不重新执行。排队和终态留在 SQLite；强制中断的执行标为 `worker_interrupted`，不会自动重放可能有副作用的操作。服务正常停止时结束当前任务，保留 `worker_stopped`。

## 完成通知

终态生成一条持久通知，QQ 会话后台领取后通过正常发送服务发出，再记录真实消息回执；不调用模型生成完成通知。通知只含状态、补丁范围、独立测试退出码和发布结果，不发送原始任务、模型思考或事件日志。

通知状态为 `pending → sending → sent`。发送和数据库确认不能组成跨系统事务：若进程在两者之间退出，通知会保留在 sending，查询时表示交付未确认，不自动重发，避免重复消息。查询任务仍能取得候选结果。该设计保证不盲目重发，不声称实现跨系统严格恰好一次交付。

## 发布与后续

源码开发任务的“成功”只表示独立工作副本产出了补丁且配置的测试通过，不应用补丁、不重启生产。

持久工作流任务（阶段 4）在通过测试后由 worker 自动发布，不设人工确认：

1. 代理开始前，把线上 `/home/qqbot/QQbot/MaiBot/workflows` 复制进工作副本并提交为基线；补丁只含在线上当前版本之上的改动。
2. 测试通过后，在发布锁内核对线上目录仍等于该基线，否则不发布（不自动合并）。
3. 先在暂存副本上用线上加载器 `src/kkbk_engine/workflows.py` 加载候选；加载错误或启用集合为空则不触碰线上。
4. 备份线上目录，按“先写目录文件、最后切换 `enabled.json`”安装；再用线上加载器自检，结果须与暂存副本一致，否则自动恢复备份。
5. 只发布 `workflows/` 下的新增或修改文件，不发布测试和源码，不支持自动删除工作流文件。无需重启：新任务读取新版，进行中的任务保持已取得的快照。

完成通知说明已发布的工作流版本和发布记录编号；自检失败会说明已自动恢复，未发布时给出原因。管理员可以让模型调用 `development_rollback` 回退最近一次仍生效的自动发布；若线上在那次发布之后又被改过，宿主拒绝回退，避免覆盖未知改动。

发布记录位于 `/home/qqbot/dev-harness/workflow-releases/<编号>/`：`manifest.json`（状态 checking → installing → verifying → installed / rolled_back / restore_failed / failed / reverted，前后文件摘要和加载结果）、`before/` 旧版本备份和 `candidate/` 暂存副本。它与维护者部署脚本的 `releases/` 分开。设置 `KKBK_DEV_WORKER_LIVE_WORKFLOWS=off` 可关闭自动发布，此时工作流任务仍只保留候选。

本轮真实教学验收已完成：候选补丁包含新工作流版本及测试，独立复测 88 passed/1 skipped，完成通知取得真实 QQ 回执。用户随后要求移除测试规则，已清理候选并撤回该消息单独产生的测试记忆；查询该任务会显示 `candidate_discarded=true`，保留验证摘要而不再提供可发布补丁。

部署入口 `scripts/deploy/deploy-harness.py` 仅供本地维护者按明确文件集合部署本项目实现；它不是给 bot 使用的发布器。每次写入前保存旧字节并记录来源、目标及 SHA-256，开发代理无法访问这些宿主发布目录。
