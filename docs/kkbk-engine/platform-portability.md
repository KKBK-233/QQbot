# 对话层跨平台迁移设计

状态：2026-10-21 新增需求与实施计划，尚未实现或部署。目标平台包括 QQ、飞书、微信；具体外部接口、账号条件和平台限制应在各适配器实施前查阅官方文档确认。本文件不宣称这些平台已经接通。

## 目标与范围

同一套日常对话、任务工具、教学和开发协调逻辑可通过不同平台入口运行。搬到新平台主要更换适配器与配置；同一部署可以选择单个平台，也可以同时连接多个平台。

沿用 MaiBot 的消息服务、模型服务、工具注册、数据库及 A_Memorix，不另写一套记忆系统。人设、工作流和工具实现可复用，历史消息、成员身份和群聊记忆的共享范围需显式配置，不能因昵称相同或账号文本相同自动合并。

```text
QQ / 飞书 / 微信接入端
          │ 平台适配：入站、真实身份、引用、媒体、发送回执
          ▼
MaiBot 宿主服务 + 统一会话接口
          ├─ 日常对话与任务分流
          ├─ 工具与版本化工作流
          └─ 开发协调 → DSH → 验证与发布
```

## 当前代码基础与缺口

- `MaiBot/src/kkbk_engine/inbound.py` 已有 `InboundMessage`，可复用文本、提及、引用与媒体组件抽象；目前身份描述及会话外围仍偏向 QQ，尚无完整的平台与账号命名空间约定。
- `config.py` 的 bot、管理员、教师及群白名单目前按 QQ 用户与群配置。应改为按接入实例加载身份配置，并保留现有 QQ 配置迁移兼容。
- `dev_worker/coordinator.py` 明确要求 `platform == 'qq'`，开发会话归属还比较原始平台与用户 ID。同一 QQ 管理员跨群控制已实现，跨平台控制尚未实现。
- 媒体和发送相关插件需逐项检查 QQ 依赖。适配器接通文字收发，不等于识图、生图回传或开发通知已可用。

## 统一接口约定

| 边界 | 约定 |
| --- | --- |
| 消息与会话 | 外层保留 platform、接入实例、租户或组织范围（如适用）、conversation_id、message_id、sender_id、时间和会话类型；@ 与引用使用结构化字段。不要只用一串群号作全局键 |
| 身份与权限 | 实际身份由已验证的平台入站事件提供。管理员在维护配置中将不同平台身份绑定为同一个内部主体；昵称、文本自称及模型参数不能创建绑定。角色权限与会话授权范围分别配置 |
| 回复与回执 | 统一发送文本、图片、文件与引用回复；平台适配器处理字数限制、上传和格式。按平台及接入实例保存幂等键和实际发送回执；超时且送达未知时不盲目重复发送 |
| 媒体读取 | 统一取得当前或引用消息的原图/文件，由适配器处理平台文件标识、下载与有效期。不存在、过期或不支持时返回明确状态，不取另一张图顶替 |
| 能力发现 | 适配器声明能否读取引用、取历史、发送图片/文件、识别提及等；引擎按实际能力开放工具或返回降级结果，不假设 QQ 合并转发等格式到处可用 |
| 记忆与教学 | 复用原记忆服务；在宿主边界保留来源平台、会话和可见范围。可共享管理员批准的方法与人设，不能默认将 QQ 群历史带到另一个平台 |
| 开发会话与通知 | 根需求来源不可变；跨平台续聊依赖显式绑定的同一管理员及已授权目标会话。查询不迁移通知；新补充决定待执行轮次的回传位置，已运行和已发送回执沿用原路由 |

边界校验由代码承担，模型只决定对话和任务动作；普通聊天保持现有调用路径，不为每条消息增加一次平台识别模型请求。

## 实施拆分与验收

1. **抽离 QQ 绑定。** 定义统一事件、身份与会话键、发送/媒体接口和能力表，以 QQ 作为第一个适配实现。旧记录通过兼容映射读取，不破坏现有消息 ID、引用和回执。验证普通聊天、silent、提及、引用图、工具回传、重复事件和开发通知。
2. **接入第二个平台。** 建议先用飞书验证平台抽象；实施前确认实际应用与账号条件、事件认证及官方接口。先完成文字、@、引用和图片，再逐项验收搜索、识图、生图、教学和开发会话；没有完成的能力明确标记。
3. **实现微信适配。** 先确定用户所指的是个人微信、企业微信还是公众号等入口，再核实可用接口与部署条件；不能将一种入口的实现当成所有微信会话都能接入。复用步骤 1 的接口，仅在适配层处理差异。
4. **迁移与并存验证。** 同一逻辑消息通过 QQ 和第二个平台适配后应产生等价的核心输入；验证同名/同 ID 不串身份、授权管理员可续聊、未绑定身份不可接管、平台断连不影响另一平台、重连不重复交付。

迁移时选择复用哪些人设、工作流、教学与记忆范围，并记录映射。搬迁不默认将两边群消息互相转发，不默认停止原 QQ 实例。具体上线切换在适配器具备验收结果后执行。

## 与主计划的关系

这是横向平台能力，基础抽象和文字接入可与阶段 4 发布能力并行设计；跨平台提供完整开发闭环仍依赖源码发布、工具发现及真实业务验收。阶段 5 主动改进和阶段 6 管理界面沿用统一的平台身份、会话和用量维度。

本次仅更新文档；不修改运行配置、QQ 登录或现有平台权限。后续是否派发给 DSH 开发，以明确的实现任务为准。
