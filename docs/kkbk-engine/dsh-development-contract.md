# DSH 开发约定与持续会话设计

状态：已确认的设计要求，尚未实现的部分见下表。本文供下一轮接入 DSH 开发提示与协调协议使用；当前 `developer_prompt()` 不会自动读取本文，本次不修改运行时、不调用开发代理。

## 目标与开发权限

开发时：对话层提出目标 → DSH 开发层实现和验证 → 发布到工作流层。

调用时：对话层提出任务 → 工作流层使用已发布的指导、执行代码与工具 → 返回结果。

工作流层承载可使用的能力：可以只有已有工具的编排指导，也可以包含新增执行代码、插件、依赖、提示词和工具入口。只有自然语言规则不等于新增执行能力已经实现。

DSH 是具备完整开发工具的执行者，允许在项目工作副本中修改整个已纳入的项目，包括人设、system 提示词、各任务提示词、工作流、插件、引擎、模型适配、依赖与测试。常规文件选择和实现细节由开发代理自主判断，不要求管理员逐文件确认，不把修改能力限制在插件接口或工作流 JSON。

开发协调层负责提供完整项目及当前生效配置的必要脱敏快照、来源和发布映射。生产凭据及 QQ 登录资料不作为源码输入；候选经验证和发布后生效。开发权限与发布范围分别记录，不能因为当前发布器只支持 JSON，就把需要代码实现的目标改写成文字规则。

## 提供给开发代理的任务约定（待接入）

以下约定应由宿主注入 DSH 开发上下文，不能只留在给群聊模型看的工作流里：

> 你是本项目的开发执行者。目标是让 bot 获得实际可用的能力，可以修改工作副本中的人设、提示词、工作流和项目代码，并运行 Shell、Git、依赖安装、测试与调试。
>
> 先检查本任务目标、已有候选、当前工具和实际发布能力。能用现有工具实现时更新编排；需要新能力时实现其代码、依赖、工具注册、输入输出接线及对应工作流。不要把可执行功能降成一份描述该功能的说明。
>
> 在已授权目标内连续推进，遇到测试失败自行定位和修复。不要因为完成一次回答、生成了补丁或通用测试通过就结束；逐项核对验收条件，并报告实际完成程度。
>
> 需要信息时向协调 bot 提出具体问题；bot 可以在同一开发会话中补充目标、证据和决策。沿用当前工作副本和已执行结果，不另起无关联任务，不重复产生外部副作用。
>
> 超出当前工作副本、发布能力或剩余资源时，如实报告阻塞点、已完成产物和下一步所需条件，保留可继续的状态。不能通过缩小原目标、写一份规则或自述成功来消除阻塞。
>
> 只有实际验收通过才将对应目标标为完成。区分开发完成、候选验证、已发布和业务可用；以测试、工具加载、发布回执及原场景复测作为证据。

“执行完”表示在资源允许时推进到约定验收结果；资源耗尽、故障或用户取消时保留明确状态与恢复点，不要求无限运行、取消超时或无限重试。

## bot 与 DSH 的持续会话（待实现）

- bot 能发起开发、读取阶段摘要和真实执行结果、回答开发问题、补充或纠正需求、继续同一会话以及取消任务。不是只提交一次，再被动接收最终通知。
- 每个开发目标绑定稳定的任务编号、DSH 会话标识、工作副本、原始需求及验收清单；同一目标的补充消息关联该会话。协议需核验当前安装版本实际支持的会话控制方式，不预设 CLI 参数。
- 开发问题进入持久待答队列。bot 能根据已有授权与证据自行回答普通实现问题，只有确实需要管理员的信息才向管理员询问。
- 任务过程保留可读的阶段、命令/工具结果、测试证据和未完成项；不依赖群聊窗口保留完整开发上下文，也不需要向 bot 暴露模型内部思考。
- 继续前核对当前进程、任务状态和消息确认记录，避免同时运行两个执行者。中断后从确认过的工作副本及结果继续，不盲目重放已执行操作。
- bot 可以从自己的失败和能力缺口组织后续开发需求，关联原始消息、复现材料和预期改善；继承管理员授权范围。当前只观察或资源不足时，不自动启动开发。

## 完整交付与验收

同一目标应覆盖“需求 → 开发 → 独立验证 → 发布 → 工具发现 → 原场景使用 → 效果记录”。发布可执行能力时，一并处理指导、代码、依赖与工具入口的版本关系。

任务范围若无法覆盖验收目标，应调整派发或明确阻塞，不向代理同时要求“安装插件”与“只改工作流 JSON”。后续任务能引用并接续已有候选，避免候选留在另一个不可见副本。

独立验证按实际改动组件选择测试；新增插件不能只依靠原引擎测试退出 0。能力验收至少包括宿主实际加载、模型发现工具、正确取得输入，以及原场景复测。未通过项保持未完成，不由“已发布某份工作流”替代。

## 当前实现与缺口

| 项目 | 当前状态 | 需要补齐 |
| --- | --- | --- |
| 开发工作区权限 | 已允许修改克隆仓中的全部项目文件 | 多仓组合副本、有效人设/提示词快照及发布映射 |
| bot 控制 DSH | 能提交、查询、取消；完成后接收通知 | 同会话补充、问题应答、继续执行与中断恢复 |
| 开发产物发布 | 工作流 JSON 可自动发布，源码只留候选 | 代码、依赖、工具入口与指导共同交付 |
| 工作流执行 | 文字指导注入工具阶段，模型调用已有工具 | 新工具发布后的发现、图片等输入接线 |
| 完成判定 | 补丁、代理退出及配置测试结果 | 逐项验收清单、业务可用证据、阻塞与后续动作 |

以上缺口不因本文提交而改变线上状态；下一轮实现时需把任务约定接入实际 DSH 上下文，并验证 bot 对同一开发会话的真实控制。
