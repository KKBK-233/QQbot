DS娘外观注册在 `maibot-plugin/ds_character.json`，附中文社区资料出处与核对日期。蓝色渐变长发、蓝瞳、呆毛、鲸鳍耳、连续连接的鲸尾和女仆装是共通身份；不同社区版本并非统一官方设定。`form=standard` 使用用户新发少女版立绘和三视图（披散长卷发、藏青长裙、较长弯曲尾柄），`form=chibi` 使用原2.5头身Q版三视图和短尾；auto在明确“少女版”时保持普通比例，包括少女版表情包，明确Q版时才使用Q版。两种形态分别注册，不继承旧麻花辫或设定板排版。

明确提及DS娘、DeepSeek娘、DS酱或鲸鱼娘，或传 `character: "deepseek"` 后，工具分离角色身份与场景要求，清除规划器旧回复里夹带的紫色短发等身份描述，保留背景颜色、表情和动作。用户明确要求染发、剪发、换装等变化时，使用 `appearance_change` 逐字引用用户原话，并提供 `instruction_message_id`；工具核对同群真人消息后才覆盖对应外观。提示词不会从机器人自己的旧回复取得外观授权。

有本群固定原图时，适配层实际附图并使用edit；已有任务父图或用户指定原图可另外提供，用于确定修改对象。其他群只使用文字注册卡，不跨群借图。配置和参考消息编号在 `maibot-plugin/character_rules.py`。注册验证会检查两种原图实际读入及请求参数，但不消耗生图用量，也不保证每次生成都一致；用户下一次生成仍需视觉验收。

群内明确纠正DS娘特征、要求“以后按这个画”或确认新参考图时，可通过同一个 `chatgpt_image` 工具使用 `remember` 保存，再由 `recall` 查看、`undo` 撤销。普通比例和Q版各自记忆；同一特征采用最新纠正并保留旧版本。具体特征逐字摘录真人原话，来源消息和作者随条目保存；图片分析推测先说明，不能把机器人自述当作用户确认。真人明确认可的生成图也可以成为新参考，原图快照留存并校验，不依赖后续聊天记录仍存在。

动态条目保存于WSL `MaiBot/data/plugins/local.qqbot-image/character_memory/<群编号哈希>/<standard或chibi>.json`。基础卡仍在插件源码中，动态纠正和新参考优先覆盖点名的外观项；后续DS娘生图自动读取，不需要每次手动查询。`remember/recall/undo` 不调用生图后端，记住不代表图片已经修好；用户明确要求改图后另用 `edit`。这是一层持久角色知识，不是模型权重训练。

独立MCP桥接工具有三个动作：generate/edit/status。MaiBot适配层另外支持remember/recall/undo角色记忆操作，记忆保留在宿主插件数据目录，不能通过外部MCP修改群记忆。每次新任务分配唯一 request_id；查询、重复传输沿用原编号，不会重复生成。父任务可继续编辑或分支，不能隐式选择别的任务的“最后一张图”。

插件1.3.0在同一工具增加`search_reference`：`prompt`填角色名及原作名等简短关键词，返回最多两张已下载原图的`reference_id`、标题、来源与尺寸；随后`generate`填写`web_reference_id`，适配层实际附原始图片字节并进入参考生图，而非仅拼接网页摘要。用户明确原图或成功父图优先，已注册角色沿用已确认参考；无固定参考的具名角色优先先搜再画，普通物体不用每次搜图。网上参考用于本次视觉设计，不自动覆盖人物画像、角色记忆或默认构图。可在群里说“@伊蕾娜 先搜赫萝的原图，参考原图画她站在秋日街道”。

图片检索使用当前依赖实际提供的DuckDuckGo/Bing图片引擎，不冒称Google图片检索。原图下载复用网页插件的公网URL校验、固定DNS地址、TLS域名校验及重定向检查；仅接受PNG/JPEG/WEBP、最多5MB、20M像素，验证在无网络沙箱完成，不使用个人浏览器或账号。搜索参考元数据位于插件数据目录`web_references/`，编号按会话隔离、30分钟过期，使用前核对图片摘要，提交后由桥接层冻结快照。找不到或无法下载原图时明确失败，不偷换缩略图或声称已附图。真实测试下载了两张伊蕾娜参考图（399×690、1838×2757）；真实SDK适配验证确认原图被加入请求，未为此测试执行生图或QQ发送。

## 图片和群聊隔离

MaiBot 用当前群的 message_id 读取附图或两层引用图，核对所属会话后导入。任务编号带宿主生成的会话前缀，别的群无法借用编号拿图；同群成员之间可以引用图片。完成后自动发回原群，持久化交付记录防止重复刷群。

媒体模块可展开宿主已保存的合并转发内容，最多四层、200个节点。识图最多读取两张，并报告来源消息编号；改图遇到多张原图要求明确指定，不默认取第一张。任务识图支持本群历史消息编号，纯文字要求可检查同作者十五分钟内的候选：唯一候选直接读取，多候选返回编号供确认，不跨群搜索。仅有摘要或宿主没有保存图片字节时仍需补充完整记录。部署任务插件后运行根目录 `repair-history-image-reading.py` 同步这项修复。

独立 MCP 客户端可由可信宿主将 PNG/JPEG/WEBP 放入 `data_dir/inbox`，然后使用 `references: ["photo.png"]` 和 action=edit。模型不能传任意路径、网址、脚本或命令。最多3张参考图（包含父图），每张不超过20MB；生成前复制快照，防止排队期间引用被替换。文件头检查不是完整解码验证。

## 后端和权限

image-use 固定源码及 SHA256，调用 `chatgpt.com/backend-api/codex/responses`；这是第三方对内部 Codex 后端的适配，不是公开 OpenAI API 的正式 SDK。仅在本机读取 Codex OAuth，令牌不会返回模型或群聊。缺少授权时先运行 `codex login` 使用 ChatGPT 登录。

Windows 兼容入口读取实际安装的 Codex CLI package.json 版本，避免旧 version.json 缓存导致后端误判。浏览器命令输出使用临时文件而非管道，外层也不等待后台进程继承的输出管道，防止永久等待。网页兼容分支保留在代码里，但当前不启用、不自动回退。

模型只有该生图工具，没有浏览器通用工具、eval、任意网址、任意输出目录。封装不是操作系统沙箱，不能撤销模型已有的 shell 权限；同用户恶意进程仍能访问本机凭据和图片。已装 Chrome 扩展本身仍有广泛浏览器权限，但 Codex 后端不调用它。Claude 配置未修改。
