`run_python(code, files_json='{}')` 是独立的 MaiBot Tool。只使用现有系统 Python 3.12 标准库，不需要模型新订阅、Docker、常驻沙箱服务或联网安装软件。可进行计算、算法校验及小型 CSV/JSON/文本处理。

每次调用以专用无登录账号 `qqbot-sandbox` 新建 Bubblewrap 命名空间，临时文件在结束后销毁。输入只能是显式传入的 UTF-8 文本内容，不能填写宿主文件路径；本版本没有接通 QQ 附件下载或群文件发送。返回的文本文件内容由正常回复流程呈现。

| 项目 | 固定限制 |
| --- | --- |
| 代码 | 16 KiB |
| 输入 | 最多8个文件，JSON和解码后的内容均不超过64 KiB |
| CPU / 总时长 | 3秒 / 6秒 |
| 进程地址空间 | 256 MiB硬限制 |
| cgroup合计资源 | 384 MiB内存、swap=0、单核25% CPU带宽、最多8个启动/运行进程 |
| 工作目录 | 16 MiB临时盘；单文件1 MiB |
| 并发 | 整个插件同时1个任务；跨进程文件锁，忙时直接返回 |
| 标准输出 / 错误 | 常规打印各8 KiB；原始管道各64 KiB，超额终止 |
| 文件回传 | `output/`下最多8个普通UTF-8文件，合计16 KiB；不递归，不跟随软链接 |
| 模型回传 | 最终结构化工具结果最多4 KiB，超额不回传大块正文 |

文件收集上限与模型回传上限同时生效，适合返回小型结果，不适合把整个文件倾倒进聊天。6秒是代码执行预算；杀进程、回收目录项等清理另有有界等待。

## 累计预算和成本

| 窗口 | 全局 | 同一会话 | 同一用户 |
| --- | --- | --- | --- |
| 滚动60秒 | 6次 | 2次 | 2次 |
| 滚动24小时 | 100次 | 20次 | 10次 |

同会话另有10秒冷却；最近连续3个任务失败后暂停15分钟。预算检查由宿主执行，拒绝时不创建沙箱、不排队。模型不能通过工具参数修改限额。宿主对沙箱工具单独覆盖模型传入的会话、用户和信任标记，身份只从真实执行上下文取得，缺失时拒绝执行。其他插件的桥接行为保留。

每次准入预扣4 CPU秒预算，滚动24小时全局最多预扣400 CPU秒；这是保守的容量预算，不是按运行成功与否扣款。失败、取消、进程异常退出和重启均不退还，防止反复取消或报错刷资源。SQLite事务保障并发预扣原子性，额度在插件/服务重启后保留。

实际CPU来自cgroup内核计数；耗时用宿主单调时钟；内存峰值是20ms采样估计，可能漏掉瞬时尖峰。记录仅包含任务编号、时间、会话/用户/代码哈希、输入/输出字节数、状态及用量，不保存代码正文、文件正文、QQ登录信息或原始用户ID。主数据库上限2 MiB，保留8天任务记录，临时回滚日志另占少量磁盘；审计写入失败即停止后续执行。中断可能缺少最终实测值，但预扣额度不会丢失。

本工具执行本地代码，不主动调用额外模型API。**规划和回复的模型token用量仍单独发生，沙箱预算不是整段聊天或整个WSL的费用上限**；4 KiB限制减少工具输出带来的上下文消耗，但不阻止其他工具或聊天本身消耗额度。管理员可只读查询：

```powershell
wsl -d Ubuntu -u qqbot -- python3 /mnt/d/code/web/QQbot/python-sandbox/usage.py
```

## 使用

群里可让 bot：“用 Python 计算这组数字的均值”，或交付 CSV 文本后让它处理。

```python
import csv, json
from pathlib import Path
rows = list(csv.DictReader(Path('data.csv').open()))
answer = sum(float(r['value']) for r in rows) / len(rows)
print(answer)
Path('output/result.json').write_text(json.dumps({'mean': answer}))
```

配套 `files_json`：`{"data.csv":"value\n2\n4\n6\n"}`。后续调用须重新交付文件，不共享工作目录。

## 隔离策略与边界

- 空环境启动，仅挂载解释器、标准库、系统动态库和可信启动器，全部只读。根目录和 `/dev`只读；仅`/work`可写，不挂载`/home`、`/mnt`、`/proc`、`/run`或配置目录。
- 固定启动器和worker由root所有且普通账号不可写。机器人只能通过精确的无参数sudo规则调用“启动固定沙箱”和“终止固定沙箱cgroup”两个入口，不能选择命令、账号、PID、挂载路径或传入启动参数。root入口不解析代码，先设置资源限额并降权，再启动解释器。
- 独立用户、PID、网络、IPC等命名空间，清空Linux capabilities，禁止嵌套用户命名空间，新会话隔离终端。
- 可信启动器在执行代码前加载 libseccomp 默认拒绝的系统调用白名单。网络套接字、fork/clone、exec、ptrace、挂载、io_uring和修改资源限额均不在白名单。直接ctypes调用系统调用也受限制。
- 不给插件宿主消息查询、模型调用、文件访问等SDK能力。工具结果始终是不可信数据，不是指令；不修改其他工具的权限。
- 超时、取消和输出超额终止整个cgroup；等内核确认无残留进程后才释放执行锁。目录洪泛回收晚于信号交付也必须等待；清理失败后熔断。排空已结束进程的管道，防止输出刷屏卡死清理。隔离组件缺失或启动失败时直接报错，不退回宿主执行。

这是与WSL共用内核的轻量隔离，**不是独立虚拟机，也不承诺抵御内核漏洞**。cgroup限制覆盖本组进程、页缓存和目录项等内核内存，但不是数学意义上绝无瞬时超限，定义见[Linux内核文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)。不适合公开承载蓄意攻击的多租户代码；这种场景应使用独立虚拟机/微虚拟机。系统库随宿主安全更新维护。Bubblewrap本身不预设完整安全策略，具体边界取决于启动参数，见[上游说明](https://github.com/containers/bubblewrap#sandbox-security)。
